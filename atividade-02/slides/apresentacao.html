2

E-commerce

Microsserviços

Por que sim

  • Escala independente: catálogo escala 50x, devolução escala 2x
  • Tolerância a falhas: recomendação cai, checkout continua
  • Deploy isolado: equipes fazem deploy sem bloquear umas às outras

Trade-off

  • Complexidade operacional alta
  • Precisa de Kubernetes, API Gateway, monitoramento distribuído
  • Consistência eventual (aceitável para catálogo)
Negócio: e-commerce fora do ar na Black Friday = milhões em prejuízo. Microsserviços isolam falhas.
3

App Bancário

Monolito Modular

Por que sim

  • ACID nativo: BEGIN → DEBIT → CREDIT → COMMIT no mesmo processo
  • Segurança: um deploy, uma porta, um perímetro
  • Auditoria: logs centralizados, rastreabilidade total

Trade-off

  • Escala horizontal limitada (escala vertical)
  • Deploy é tudo-ou-nada
  • Risco de acoplamento se os módulos não forem bem definidos
Negócio: inconsistência de saldo = processo judicial + multa. Simplicidade operacional reduz risco.
4

Jogo Multiplayer

Cliente-Servidor (WebSocket) + Eventos

Por que sim

  • Latência mínima: WebSocket persistente, sem overhead HTTP
  • Servidor autoritativo: previne trapaça, estado verdadeiro no server
  • Escala por sala: cada partida = 1 game server dedicado

Trade-off

  • Game server stateful (se cair, partida é perdida)
  • Complexidade de sincronização de estado
  • Backend assíncrono via eventos (ranking, perfil)
Negócio: lag = frustração = desinstalação. Latência baixa retém jogadores e gera receita (skins, battle pass).

6

Reflexão: por que não existe "bala de prata"?

  • Todo estilo tem trade-off. Microsserviços escalam, mas complicam. Monolito simplifica, mas não escala infinitamente.
  • O contexto de negócio muda tudo:
    • Orçamento: startup com 3 devs ≠ empresa com 200 engenheiros
    • Time-to-market: monolito vai ao ar mais rápido, microsserviços evoluem melhor
    • Equipe: a arquitetura reflete a estrutura do time (Lei de Conway)
  • A pior decisão: escolher por hype ("todo mundo usa microsserviços") em vez de evidência ("meu sistema precisa disso?")
A melhor arquitetura resolve o problema de agora com o menor custo de complexidade, deixando a porta aberta para evoluir.
